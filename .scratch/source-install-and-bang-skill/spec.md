# Bang v2 源码安装与宿主对话中的 `$bang` 技能

Status: ready-for-human

## Problem Statement

我在不同目录里学习不同专题，希望打开终端里的 Codex 或其他支持该技能的宿主就能开始记录。目前从源码使用 Bang，需要自己组合项目初始化、专题选择、会话绑定和白板访问等操作。换一个会话、停止记录或只想回看旧白板时，我还需要知道哪些对话会进入专题，以及白板上的结论来自哪一轮问答。

## Solution

在源码仓库运行一次安装脚本，然后在学习目录的宿主对话里使用一个技能。`$bang` 开始或接续当前会话的采集并回复白板链接；`$bang status` 列出各专题的链接、采集会话与整理进度；`$bang stop` 结束整个项目的采集并停止后台。用户自行打开链接，在可交互白板上沿路标回看原始轮次记录（Episode）。

## User Stories

1. 作为源码用户，我希望安装一次即可在多个学习目录调用技能，以便新建专题时直接开始讨论。
2. 作为终端用户，我希望在宿主对话里完成日常操作，以便无需配置 shell 短命令或记住源码位置。
3. 作为已有自定义技能的用户，我希望安装过程保护我的内容，以便重装时保留自己的改动。
4. 作为正在学习的用户，我希望自行决定何时更新，并让运行中的项目继续采集，以便升级期间保留会话绑定。
5. 作为源码用户，我希望更新失败后仍能使用原入口，以便继续访问已有项目。
6. 作为新专题的作者，我希望首次调用时按目录名创建专题，以便省去初始化和命名步骤。
7. 作为已绑定的用户，我希望重复调用时沿用原绑定，以便继续原来的采集区间。
8. 作为进入已有项目的用户，我希望自动沿用唯一活跃专题，多项可选时由我选择，以便原文进入正确的白板。
9. 作为同时讨论两个问题的用户，我希望两个会话可以绑定同一专题，以便打开新窗口后原窗口仍能继续贡献问答。
10. 作为跨宿主用户，我希望回执说明是自动监听还是按轮投递，以便知道哪些讨论会保存。
11. 作为尚未配置模型的用户，我希望先保存原文并看到配置提示，以便稍后整理已经发生的讨论。
12. 作为终端用户，我希望收到可自行打开的专题链接，也能重新获取过期链接，以便决定何时查看白板。
13. 作为回看项目的用户，我希望直接列出所有专题各自的链接和进度，以便在未绑定的会话里也能查看任一专题。
14. 作为专题作者，我希望分别看到实际保存的轮数和最近成功整理的进度，以便知道哪些问答已经可以回读、哪些已经整理。
15. 作为修订原文的用户，我希望修订保留各版并只计一轮，以便保存历史时轮数仍与实际讨论一致。
16. 作为结束记录的用户，我希望一次停止当前项目的所有采集区间，以便停止后继续交谈的内容留在专题之外。
17. 作为刚完成一轮讨论的用户，我希望停止前已完成的有效问答即使尚未被读取也能保存，以便最后一轮的去留取决于完成时间。
18. 作为遇到原文读取失败的用户，我希望照常停采并知道哪个会话的末尾未能核实，以便判断已保存记录的完整性。
19. 作为停采后回看的用户，我希望查询状态能重新提供白板链接并保持停采，以便浏览历史时不会恢复记录。
20. 作为经历进程意外退出的用户，我希望原有绑定能够续采，以便恢复有效区间里的问答。
21. 作为白板读者，我希望从整理出的路标直接打开对应的用户提问与助手回答，以便核对总结的依据。

## Implementation Decisions

- 以 Bang v2 的 CLI、项目守护进程和交互白板为基础。源码安装负责在当前用户范围内注册技能，并让技能能定位执行入口。项目初始化只负责项目数据与配置。
- 用户更新源码后自行重跑安装。更新成功后，新启动的项目使用新版，正在运行的项目沿用原版至下次启动。重复安装保护用户自行编写的技能，安装失败保留上一次可用入口。
- 新目录首次调用按目录名创建专题。重复调用优先沿用当前会话的有效绑定。未绑定时，按用户点名的专题或唯一活跃专题绑定；有多个候选且未点名时，先列出选项再开始采集。另一会话绑定同一专题不影响原绑定，回执列出该专题正在采集的会话。显式解绑单个会话只结束它自己的采集区间。
- 沿用 v2 的轮次过滤与绑定起点规则。Codex 绑定且监听已生效才报告“正在自动记录”。依赖宿主投递时报告“白板已就绪，宿主提交的问答会保存”。缺少整理模型时仍接收有效原文并报告配置状态，配置完成后可整理已保存的问答。
- 所有白板打开请求都在终端回复一次性专题链接，浏览器由用户自行打开。空目录查询状态只报告尚未初始化。已有专题时复用或按需启动服务，每个专题一行列出名称、独立访问链接、采集中的会话、已保存轮数与最近成功整理进度。查询保持已有会话绑定和采集区间。
- 原文轮数按专题内实际发生的来源轮次计算。同轮的重投或修订只计一轮，不同轮次即使正文相同也分别计数。最近成功整理的进度只取成功结果。
- 按 ADR 0001，主动停止以项目为范围，以收到停止请求时为界。保存所有有效绑定中此前已完成且符合规则的问答，排除当时仍在生成的回答。完成原文保存即可停止服务，无需等待模型整理。白板、历史和原文保留。
- 若某会话的原文暂时不可读，仍立即结束所有有效绑定并停止监听，回执列出未能核实尾部的会话。恢复后仅可补入能证明在停止前已经完成且符合规则的轮次。重新绑定只为指定会话开启新区间；进程意外退出则保留有效绑定和游标，恢复后继续原区间。

## Testing Decisions

以已确认的用户路径作为联合验收入口：在隔离环境完成源码安装，从真实宿主对话调用技能，由用户打开返回的链接，在浏览器中检查同一专题的实际白板和来源问答。自动化复用现有临时项目 CLI、回环服务、Codex 来源记录及 Episode 回读测试。断言回执、链接目标、采集范围与可见内容，避免绑定内部调用顺序或数据库表结构。

| 场景 | 可观察的通过条件 |
| --- | --- |
| 安装与更新 | 从两个独立目录调用同一已安装技能。项目 A 采集中更新，A 沿用原版继续记录，新启动的 B 使用新版。另验证重装保护自写技能、安装失败后原入口可用。 |
| 专题选择 | 在新建的 gdn 目录得到同名专题。重复调用沿用绑定。未绑定会话在唯一候选时直接接续，在多个候选时选定前没有专题收到该会话的问答。 |
| 多会话主动停止 | A、B 绑定同一专题。收到停止请求时，A 有已完成但未读取的一轮，B 有正在生成的一轮。A 的原文可回读，B 的这一轮及停采期间的讨论均跳过。随后只在 B 重绑，只有 B 的新讨论入库。另用进程强杀验证有效绑定恢复。 |
| 来源不可读 | 停止时暂时移走 A 的来源文件。所有会话均停采，回执点名 A。恢复来源并重新启动后，停止以后的问答始终留在专题之外。 |
| 状态与链接 | 在空目录查状态后没有项目文件。在有三个专题的项目，从未绑定会话查询，逐一打开各自的链接，核对采集会话和整理进度。主动停止后再次查询能打开白板，继续聊天不会增加轮数。过期链接可重新获取。 |
| 采集与整理 | 在没有图形桌面、没有整理模型的环境验证绑定、原文回读和回执。要求“打开白板”时仍只打印链接。配置模型后，已有原文可整理；未成功整理的轮次不能出现在成功进度中。 |
| 轮数与修订 | 保存三轮，其中两轮正文相同。修订第二轮并重投同一版，仍显示三轮；第二轮的两版原文均可回读。 |
| 宿主能力 | 在 Codex 和依赖逐轮投递的宿主分别核对启动回执，从对应专题回读自动采集及宿主实际提交的问答。 |
| 前后端联合验收 | 在已配置模型的环境中从 Codex 启动，实际讨论并完成整理。复用 GDN 用例，从白板上的“只更新第一列？”找到成立条件、纠偏依据及对应 Episode；保留中途与最终检查结果、画布截图和抽查的 Episode 引用。能打开服务页面只是链路中的一步。 |

## Out of Scope

v1 运行时、验证包、原生 helper、迁移脚本和旧安装流程已退出维护。本功能的日常交互限于一个宿主技能的三个动作；单独的 shell 快捷入口与专门匹配“重试这个会话”的技能分支均不在本次交付范围内。整理器已有的会话级恢复能力沿用 v2 规格。
