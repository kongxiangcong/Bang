# Legacy project migration — ticket 37

Public Runtime/JSON-stdin CLI and protected HTTP provide `legacy-preflight`, `legacy-stop`, `legacy-migrate`, `legacy-history`, and `legacy-archive`. The browser's **旧项目预检与迁移** panel exposes selection, stop request, read-only report, semantic history, original sources, native visual preview, explicit offline/replay confirmation and an independent-project opening link.

Selection is `{kind:"session"}` for `.bang/sessions/pim.json`, or `{kind:"companion",topic:"safe-id"}` for the exact topic's `state.json`, `board.json`, `updates.jsonl`, `sources.jsonl`, `view.json` and optional `discussion.md`. No project scan, transcript following, model-run reading, credentials, host configuration, package upgrades or arbitrary input/output path is permitted. Input is bounded to 32 MiB; the existing complete-backup package limit is also enforced. Symlink components are refused. Missing actual saved scenes, conflicting duplicate identities, broken source references, incomplete committed revision/source counts and a board differing from event replay block migration.

`legacy-preflight` never changes legacy files. It returns exact file byte counts and SHA-256 hashes, a combined selection fingerprint, counts, writer status, endpoint uncertainties and replay states. Runtime initialization can create its normal private runtime metadata; “read-only” describes the selected legacy data. Equal duplicate source/event records deduplicate by identity; conflicting reuse fails. Companion state and processed-turn IDs establish the committed boundary. An interrupted uncommitted tail is rejected, not silently dropped.

`legacy-stop` requires `{...selection,confirm:true}`. It invokes the actual old companion stop command, changing only that command's enabled flag. An existing lock file blocks migration; the command never kills a PID or deletes a stale lock. Legacy stop allows an already-running round to drain. Old browser middleware has no ownership protocol: the user must close every old editor/server and acknowledge offline operation. Hash checks before and after publication catch observed changes, but cannot supply an OS-lock guarantee against an uncooperative old writer. This limitation is shown in the UI.

`legacy-migrate` requires `{...selection,fingerprint,confirmOffline:true,confirmReplay:true,confirmUncertainties:true}` from the inspected report. It creates an independently allocated project under `.bang/restored-projects/`, using a deterministic fingerprint allocation and ticket 36's closed-schema verifier, SQLite creation and staged-directory publisher. It never overwrites the existing project. All sources and old execution authority remain inactive; new host authorization is required. Counts, package hashes and persisted replay state are verified before returning the new-project link. Retrying the same unchanged source returns the same destination and receipt. An edited destination is rejected, never overwritten. Failed publication leaves original data intact; the same request can retry after the external obstacle is removed.

Stable `bangNode` identities become knowledge cards. The **actual saved bound label**, including manual edits, supplies the current body; deleted shapes remain deleted and create deletion intents even without an older event. Standard coordinates/sizes use the existing integer projection; editorExtras retain fractional coordinates, sizes, angle, styles, group IDs and routing. Rendering preserves saved legacy layering and exact native size when its rounded standard value still agrees. Known deletion identities cannot be recreated. Unknown objects remain annotations. Visual/semantic endpoint disagreements preserve their original arrow and bends as an annotation, record both endpoint claims as **needs confirmation**, and create no knowledge relation. Matching endpoints can become unclassified standard relations; legacy labels do not manufacture support/causality semantics.

Every unique legacy event has a native history revision reconstructing its semantic content. These revisions are explicitly labelled `event-reconstruction`: the old implementation did **not** save a native scene per event, so historical geometry is deterministic reconstruction, not an invented original snapshot. The final revision is labelled `actual-saved-scene`. The original events, sources, final saved scene, companion state, discussion, file hashes and uncertainty report remain in persistent migration provenance. `legacy-history --topic legacy` reads them publicly. Legacy source records are not forged into authenticated CompletedTurns or queued for automatic replay. Complete backup retains both the reconstructed revisions and exact provenance without adding database tables.

`legacy-archive` is an additional opt-in operation: `{...selection,fingerprint,confirmArchive:true}`. It requires an already verified migration, unchanged offline source and exact hashes. It stages a private immutable archive copy of only the inspected files under `.bang/legacy-archives/<fingerprint>/`, verifies and atomically names it; retries verify existing bytes. **The originals are deliberately retained even after archive confirmation.** No automatic deletion or relocation is performed.

## Evidence and limits

Windows 11, Node 25.8.1, bundled native owner, actual SQLite/filesystem/HTTP and actual headless Chrome; temporary fixture projects only. Fixtures use the frozen ticket 01 session and actual `runCompanion init/once` plus `createCompanionView.saveScene` with a synthetic model process at the existing public process seam. No personal legacy project or real model/credentials were used.

RED/GREEN observations: unknown preflight/migrate operation; unknown explicit stop; absent-source preflight accepted; missing archive operation; saved deletion without an event could be recreated. Each has a public regression. One test initially assumed `history-preview` wraps its result in `.state`; the assertion was corrected to its documented direct state. A dependency-junction creation was sandbox denied, then approved execution created only a worktree-local junction to existing dependencies. No dependency target was removed or modified.

Executed during development: 21 migration/backup/restore public regressions passed; four migration tests passed after later archive/deletion safety additions. Production build passed with the existing bundle-size warning. Actual Chrome passed preflight, native saved preview, explicit offline/replay confirmation, independent migration, saved human knowledge body, exact native angle/width and reload. Final integrated commands/results are recorded below after merging the current integration branch.

Not claimed: physical power-loss atomicity, Windows 10/Linux migration matrix, real Codex/DSH historical completeness, malicious concurrent old-writer exclusion, reconstruction of unavailable historical native scenes, or automatic semantic confirmation of contradictory endpoints. A format or record outside the explicitly accepted legacy contracts fails visibly instead of being declared migrated.
