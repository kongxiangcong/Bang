# Human intent and proposals — ticket 19

Public CLI: `proposals --project DIR --topic ID` and `proposal-review` with JSON stdin `{id,decision:"accept"|"reject"}`. Protected HTTP exposes GET `/:topic/proposals` and POST `/:topic/proposal-review` under `/api/canvas`. The page compares the existing object, proposed operation, source content, conditions and uncertainty, then shows the durable decision/commit receipt. Adoption does not silently refresh an edited page.

Only authenticated primary user content in a CompletedTurn can authorize a direct replacement. The first release recognizes the complete, anchored commands `请将白板卡片「ID」正文改为「TEXT」` and `请删除白板关系「ID」` (请 and final Chinese punctuation optional). IDs are exact stable board identities; arbitrary model interpretations cannot grant authority. Unsupported phrasing, hypothetical language and unclear targets remain suggestions requiring explicit adoption. The parser deliberately does not claim general natural-language understanding. Assistant promises never become commit receipts.

Ingestion captures the authorized field versions with the source, before queue/model waits. A later manual semantic edit invalidates old authority, including edit-away-and-back. Geometry-only movement remains compatible. Accepted changes use the same prepared-intent publisher and remain manual intention with discussion source/conditions separately retained; acceptance never marks knowledge true. Current model operations cannot change manual structure. Structure-rule authoring belongs to ticket 31; unsupported structural output is rejected, not implicitly authorized.

Protected replacements and relation deletions become durable proposals in the existing Organizer task body. Adoption checks the full semantic read subgraph and knowledge/field versions, then publishes through the shared coordinator. A deterministic operation receipt recovers a publication-before-decision retry. Rejection records the object/intent, baseline, source content and receipt. Once an object/operation has been rejected, later model candidates remain suppressed regardless of text hashes, paraphrase, unrelated additions, changed conditions, claimed evidence, or baseline changes. Suppressed candidates retain their actual source and comparison material but never become pending automatically. An explicit human reconsideration is required; no automatic substantive-evidence classifier is claimed. Deleted identities and deleted endpoint pairs remain protected against resurrection.

Project backups retain decisions and rejection identities, freeze pending proposals, and freeze explicit source authority. Restored pending proposals cannot be adopted. A fresh, explicit reconsideration preview in the restored project is required; old preview keys cannot authorize it. No new persistent table is introduced; the closed backup registry remains unchanged and validation rejects unfrozen imported authority.
