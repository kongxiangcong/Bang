# Context delivery contract — ticket 22

ContextBridge is independent of SessionConnector reception and OrganizerExecutor. It runs at the trusted main-host user-utterance-start boundary, before assembling that turn's model input. The native owner captures the committed revision in its normal short operation queue. Later saves affect the next utterance. Retrying the same exact workspace/bridge/binding/turn returns the original snapshot, including across Runtime reopen; it never recaptures a later revision. Five-minute query capability expiry requires a new host turn rather than silently changing the old cut. No draft is read.

## Authentication and public operations

Owner CLI `context-register` takes `{id,host,versions,publicKey}` with an Ed25519 key. Controlled development may explicitly reuse a provisioned connector key with `{id,connectorId}`; this still creates a separate registry and purpose. Registration is absent from browser HTTP. Real adapters should provision independent bridge keys. A valid SessionConnector signature is insufficient for an independently keyed bridge.

CLI JSON stdin operations: `context-start`, `context-query`, `context-ack`. Protected HTTP equivalents are POST `/api/canvas/session/context-start`, `context-query`, `context-ack`; status is GET `/api/canvas/:topic/context-status` (CLI `context-status --topic ID`). Browser capability alone grants no delivery acknowledgement or host authority.

Each request is `{topicId,turnId,...fields,proof}`. The proof uses the existing signed host/version/instance/session/workspace/primary-role/scope/time/nonce format, plus `purpose` equal to the command, `bridgeId`, and `requestHash = SHA256(JSON.stringify(requestWithoutProof))`. Sign the base64url payload bytes with Ed25519 as in the connector protocol. Matching the exact current bound session and workspace is mandatory. Nonces are single-use and durable; fresh proofs can retry the same turn. Query/ack additionally require the random turn capability returned by start. An old binding, foreign turn/topic/workspace, replayed proof, tampered request or browser boolean is rejected.

`context-start` accepts optional `budgetBytes` (2048–32768; default 16384). Its envelope is explicitly `sourced-state-data`, with `instructionAuthority: none`. It contains the pinned revision, usable cards, semantic relations, original metadata/conditions/uncertainty and withdrawn identity status, using the shared `knowledgeContext` projection. Discussion lineage is not independent verification. Withdrawn bodies are excluded from usable cards; explicit detail is labelled `validAsKnowledge:false` and preserves original provenance without supplying current source support.

The critical index covers card/relationship additions, changes, deletion and validity changes since the last delivered revision of the binding (or all existing knowledge for the first delivery, including revision zero). Exact manual wording is retained in cards or pinned read-only detail. Index/card/relation/withdrawal omission counts are explicit; a small budget never silently pretends coverage. Selection is deterministic board order, not a relevance-quality claim.

Read-only `context-query` accepts `{token,kind,offset?,limit?,id?,textOffset?}`. `changes` and `withdrawn` page at most 20 identities; `item` reads only the pinned object with text windows of 4096 UTF-16 units and `nextOffset`; `source` reads only exact source IDs used by the pinned usable knowledge, with original version/text and `independentEvidence:false`. Oversized query results use `encoding: json-fragment`, 4096-unit `text` windows and `nextTextOffset`; concatenate and parse JSON. Query responses stay below 32768 bytes even with unusually large valid identities/metadata. No query can mutate a board or escape into arbitrary files, sessions, revisions or source records.

`context-ack` takes `{token,outcome:"delivered"|"offered"|"unsynced",envelopeHash}`. An adapter with only observable stdout handoff records `offered`. `delivered` requires the host's exact receipt. Only a valid scoped signature and hash of the exact envelope can acknowledge receipt. First terminal status wins. Receipts after the two-second Runtime deadline remain unsynced, and abandoned pending attempts become visibly unsynced after the same deadline. Receipt persistence survives reopen. `modelUse` remains `unknown`.

The optional signed `bindingId` pins the exact active source row in addition to its session identity. The critical index also includes changes and withdrawn objects since the last offered cut, so subsequent context can correct a snapshot the host may already have seen. `fromRevision` still identifies the last confirmed delivery.

## Bounded host execution and UI

`runtime/native/context-bridge.mjs` exports the controlled adapter boundary `deliverContext({call,deliver,timeoutMs,budgetBytes})`. `call` signs the exact public command and scope; `deliver` receives the envelope, its hash, a scoped query function and AbortSignal, and returns an exact `{accepted:true,envelopeHash}` host receipt. The helper caps the whole start/deliver/ack path at 10–1500 ms and permits at most another 200 ms to record failure. It returns `continueConversation:true` and a manual `knowledge-context` fallback on failure. A late response cannot change a timed-out delivery green. Host/model waits are never in the Runtime operation queue or a SQLite transaction. The helper makes no model call.

The editor shows pending, offered, delivered or unsynced revision and turn, always with model actual use unknown. The manual read button explicitly reads current committed knowledge (which may be newer than an earlier pinned turn); it does not acknowledge automatic delivery. Existing displayed/head revision, reception and Organizer status remain separate. Real-host automatic support remains unverified and is labelled accordingly.

`context_turns` belongs to the closed backup schema. Exports preserve audit/envelope records, freeze them and remove token, query snapshot/source bodies and expiry authority. Registry and proof tables are excluded. Restore rejects unfrozen context authority and never resumes old capabilities; original project records continue independently.
