# Answer source versions — ticket 21

The existing signed CompletedTurn boundary retains distinct `(binding namespace, turnId, versionId)` identities. A new version becomes that turn's current source; earlier versions and their original user/answer text remain addressable. Repeating the same version/content is idempotent and cannot reselect an older version. Reusing an identity for changed text still fails. Identical text hashes across distinct versions are not deduplicated. Binding identity includes the trusted connector/host/installation/session namespace; there is no cross-host text-hash inference of lineage.

`turn-status` / protected GET `/api/canvas/:topic/turns` now return `versions` with `id`, `bindingId`, `turnId`, `versionId`, `sourceHash`, `current` and `processing`. Obsolete pending work becomes `superseded`; already organized history retains its processing receipt separately from currentness. `turn-source` / protected GET `/api/canvas/:topic/source?id=...` return the selected original text, currentness, `currentVersionId` and immutable identity history. Mutable processing status stays in `turn-status`, so backup freezing does not change original source inspection. The editor offers explicit original-answer selection, labels historical/current versions and reports processing status. Viewing history does not change source selection or automatically refresh a board draft.

The ingestion transaction persists source identities, pointer changes, queue/cursor/receipt and, when needed, the common prepared publication intent together. The same publisher/recovery protocol confirms the evidence revision before a successful ingestion reply; a retry reconciles any prepared revision before returning its durable duplicate receipt. No second board projection or new persistence table exists. Full backup retains source versions, currentness, evidence and revision history and freezes source authority/pending work under ticket 36's existing policy.

Source replacement marks exclusively superseded-source knowledge `needs-review`, without replacing its text, manual attribution, geometry, role, conditions or uncertainty. Recorded dependencies propagate the withdrawal. A card explicitly supplemented with another current source retains that support (`basis.status: retained`); this is not verification of factual truth. Its obsolete source references remain in committed/history state but are removed from the existing shared `knowledgeContext` projection. Reviewed independent human assertions remain intact. Source validity and manual wording stay separate.

An obsolete running result cannot publish. Superseded failed/cancelled attempts do not block organization of the new version; existing project pause, budget and native process-exit constraints remain in force. Pending proposal adoption or reconsideration cannot reinstate a superseded source as current evidence. Model output cannot clear review state; explicit review and revised-source analysis continue through existing operations.
