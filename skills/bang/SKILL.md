# Bang

由当前对话模型理解内容，Bang 负责显示、编辑和保存。先明确这次讨论想弄清什么，再判断分类、先后、关联、支持或修正关系，最后选择局部表达。便签、树、思维导图和流程只是可组合的表达，不是固定模板或必填栏目。保留文字推导、成立条件和原文依据，区分对话陈述、假设、未知与推断。

## 启动与读取

本技能随 Bang 项目交付，路径是项目根目录下 `skills/bang/SKILL.md`。未安装到宿主技能目录时，用户可以在对话中引用这个文件；安装后可用 `$bang`。不宣称本地文件已自动注册为插件。

在 `prototypes/whiteboard-integration` 运行 `node bang.mjs context`，优先复用现有 `BANG_URL` 指向的服务。默认地址为 `http://127.0.0.1:5180/`；默认服务未启动时执行 `npm run dev`，保持服务运行，再读取 context。

打开或复用该地址的浏览器白板，再提交更新。浏览器负责将 pending 事件应用到实际场景并保存 `appliedEventIds`，仅启动服务不能完成这一步；将实际使用的白板链接提供给用户。

context 包含当前可见对话、已保存画布上的实际文字和位置、来源元数据、待应用事件与待接受建议。先让现有 pending 事件在浏览器落盘，再以当前手改内容为上下文；同一讨论继续使用已有 id。只有用户要新建讨论时运行 `node bang.mjs reset --empty --id <topic>`；reset 会清除当前活动会话，不作为每次调用的准备步骤。

## 整理与继续

读取 [增量协议](references/protocol.md)，只输出本次受影响的节点、关系和区域。把新对话原文与增量事件写入项目内 `.bang/submissions/<event-id>.json`，然后执行 `node bang.mjs submit <文件路径>`。完成标准是服务接受事件且白板的 `appliedEventIds` 包含它；用 `context` 核对即可，不必反复全量测试。

短文字留在图上，解释、推导和来源放在节点元数据。新证据修正旧判断时，保留旧前提为何失效以及当前结论的适用范围。关联已有对象时复用 id；用户手改与新整理冲突时交给待接受建议，保留当前文字和位置。提交成功后简短返回白板链接和实际变动，不往界面添加教程、提醒或演示说明。

## 回放

用户要求回放时才使用 `node bang.mjs next` 或白板播放操作。PIM 回放是已整理的样例事件，按原文一条一条显示；默认每两轮完整问答更新，最后不足两轮也收尾。它验证增量流程，不代表运行时调用了另一个模型。后续新对话由当前模型继续整理并通过相同 submit 入口加入。
