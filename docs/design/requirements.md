# Bang 通用需求

本文是适合源码仓库保存的需求摘要，不包含个人对话、原始研究案例、账户资料或用户工作区内容。它描述产品目标，不表示这些功能已经实现或通过验收。

## 使用分工与入口

用户负责围绕问题自然对话，并主动提交整轮内容。一轮可以包含多次提问、回答、追问和纠正。Bang 负责保存原文、理解内容、生成图，并增量维护对应专题的同一份层次化画布。用户手改是可选能力，不是系统工作的前置条件。

两个目标入口是：Bang 自有对话界面，以及供其他 agent 在用户指定轮次调用的独立技能或接口。它们应复用相同的专题、轮次、来源、增量更新与手改保护逻辑，不各自产生脱节的图。

广泛接入不同对话来源是目标，不承诺无需集成即可读取任意闭源平台。必须能获授权地取得对话，或由用户导入可取得的原文；具体协议、平台兼容性和部署方式尚待验证。

## 画布如何演进

专题独立管理，可以从空白开始或接续已有理解。提交一轮后保留原文，再局部增加、修正或归并相关内容；没有新理解时，允许只保存原文而不改图。不要为每条消息生成节点，也不要每轮重画整张图。

概念可以先散放、不连线。根据实际含义选择结构、流程、依赖、问题或决策等局部表达，不强制某种图类型或系统架构模板。用户可以深入模块子图，再返回主线；层级表达讨论范围，连线表达概念关系，不混成严格树。

默认保留对话为主的体验，由模型静默维护节点短说明，原文按需查看。长总结不作为每轮必做流程。图可以随理解逐渐复杂；新关系用短暂、局部的动效提示，不全图反复重排或持续闪烁，用户操作优先。

## 来源、不确定性与用户修改

原始回答中的说法不能因为被画进图就变成事实。保留来源和条件，区分原文声称、待核实内容与模型推断；矛盾双方应可回看，不因某段回答更晚就自动采信。

用户可以修改文字和布局，修改进入后续讨论依据，不能静默丢失。具体冲突策略、版本恢复和确认方式尚待决定；原型中个别分支的行为不等于已经选定产品策略。

用户看到的是连续讨论体验，不拆成导师与记录员两种职责。Bang 具有自己的组织和维护能力；讨论技能可以被调用或借鉴，不要求通过开发某个讨论技能来实现整个产品。

## 独立持久工作区

目标是独立于程序源码、可配置并持久保存数据的工作区，统一管理专题、轮次原文、图、来源关联和用户修改。两个入口共用同一工作区。具体路径、目录结构、文件格式、数据库及多用户能力尚未确定。

访问范围、向模型或外部 agent 发送的内容、敏感信息处理和备份去向应明确，不默认暴露整个工作区或无关专题。应能备份和恢复原文、图及其关联并继续讨论，而不仅保存图片；具体权限、备份、加密、同步和迁移方案仍待验证。

## 当前原型与待开发范围

现有原型只提供脚本演示和部分本地交互。独立专题管理、主动提交整轮、真实内容理解、模型驱动的增量更新、外部调用接口、持久工作区及可靠备份恢复仍需开发或验证。

下一步应先检验一条最小可交互体验及其更新约束，再接真实对话的窄闭环，用实际反馈决定扩展范围。源码仓库的建立与克隆不意味着已经部署、启动服务或批准完整生产实现。
