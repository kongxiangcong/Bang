# Bang v2 源码安装与 `$bang` 技能设计

## 已确认的实施基线

本方案面向当前 Bang v2。源码安装和聊天入口复用 `packages/adapters` 的 CLI 与 `packages/core` 的项目守护进程。v1 已退出维护，其发布包、原生 helper、白板原型、迁移脚本及配套安装验收均从本方案移除。

v2 仍使用冻结的 Q01–Q20 用例和评分规则评估整理质量。验收要求见 [v2 规格](../../.scratch/bang-v2/spec.md)。

## 用户希望完成的事

用户克隆仓库后，希望通过一个短安装入口准备好 Bang。进入学习目录后，可在聊天中用 `$bang` 开始记录专题讨论，用 `$bang status` 查看绑定和整理进度，用 `$bang stop` 停止项目后台。由用户更新源码并重跑安装脚本。成功后，新启动的项目使用新版；正在运行的项目继续使用原版，保留有效绑定，下次启动时采用新版。安装失败时原先可用的入口仍可用。安装过程保护用户自行编写的技能。

## 调用位置

用户在终端启动 Codex 或其他支持该技能的 Harness CLI，然后在其对话输入框发送 `$bang`、`$bang status` 或 `$bang stop`。`status` 和 `stop` 都属于同一个 `$bang` 技能。安装脚本在普通 shell 中执行一次；日常使用只需进入宿主对话。技能内部调用 v2 CLI 时使用安装阶段记录的入口，无需用户将 `bang` 加入 shell 的 `PATH`。

## 已确认的使用约定

- 源码安装一次，将技能注册到当前用户的 `~/.agents/skills/bang/SKILL.md`。在新目录首次调用 `$bang` 时初始化项目；`bang init` 只负责项目数据和配置。
- 同一专题可同时绑定多个会话。在会话 B 启动时保留会话 A 的绑定；回执列出该专题正在采集的会话。单独结束 A 的采集可显式解绑 A。
- `$bang stop` 结束当前项目所有会话的采集区间并停止后台，保留已入库原文、白板和历史。之后即使重新启动服务，停采期间的轮次也跳过。再次在会话 B 调用 `$bang` 只为 B 开启新区间。意外退出仍按 v2 的有效绑定与游标恢复。
- 验收时将 A、B 绑定到同一专题，分别采集一轮；主动停止后各讨论一轮；在 B 重新绑定并继续讨论。核对两轮停采期间的问答均未入库，且 A 保持停采。另用进程强杀验证有效绑定的断点续传。

## 专题选择、停止与查询

- 新目录首次调用 `$bang`，以目录名创建专题并绑定当前会话。再次调用优先沿用当前会话的有效绑定。会话尚未绑定时，沿用唯一活跃专题；有多个活跃专题且用户未点名时，列出选项，选定前保持未绑定。
- 收到主动停止请求时，为项目内每个有效绑定确定采集终点。终点前已经完成且符合采集规则的问答应全部入库，仍在生成的回答排除。原文保存成功后即可完成停止，无需等待模型整理。
- 项目未初始化时，`$bang status` 仅报告“尚未初始化”。在已有专题的项目中，复用或按需启动项目服务，按专题逐行列出名称、各自的白板链接、正在采集的会话、已保存原文轮数和最近成功整理的进度。即使当前会话尚未绑定，也直接列出全部专题。主动停止后再查状态，回执显示“白板服务已启动，当前无会话正在采集”。查询保持各会话原有的采集边界。

## 终端回执与异常情况

- 启动成功后，在终端输出当前专题的一次性访问链接，由用户自行打开。用户明确要求“打开白板”时也只输出链接。技能通过 `bang open --topic <专题> --url` 取链接。链接失效后可再次调用 `$bang status` 获取新链接。
- 启动回执按实际采集能力说明：Codex 会话绑定成功且监听生效时显示“正在自动记录”；依赖宿主逐轮投递时显示“白板已就绪，宿主提交的问答会保存”。
- 尚未配置模型时照常接收原文，在采集方式后附注“整理模型尚未配置”。完成配置后，已保存的原文可以参与整理。
- 停止时遇到原文文件暂时不可读，仍立即结束全部有效绑定并停止监听。回执列出无法核实尾部轮次的会话。恢复时只允许补入能证明在停止边界前已经完成、且符合采集规则的轮次。
- 已保存原文轮数按专题内的实际对话轮次统计。同一轮的修订保留各版原文，计数仍为一轮；两次独立发生、正文相同的问答计为两轮。

## 前后端一起验收

在完成源码安装且已配置整理模型的环境中，通过 Codex 对话输入框调用 `$bang`。用户自行打开回执中的链接，继续在已绑定会话中讨论。整理完成后，在同一专题白板上查看产生的路标，打开来源，核对用户提问与助手回答均来自刚才的讨论。随后用 `$bang status` 核对进度，并用 `$bang stop` 验证停止后的采集边界。

源码安装、技能入口、采集、整理、交互白板和原文回读贯通后一起验收。白板复用 [GDN 原文溯源议题](../../.scratch/bang-v2/issues/03-gdn-canvas.md) 的检查点、截图与 Episode 引用。

## 验收场景

1. 在新建的 `gdn` 目录调用技能，得到同名专题。在已有多个活跃专题的项目，从未绑定的会话调用，确认选择前没有任何专题收到该会话的讨论。
2. 两个绑定会话同时存在。收到停止请求时，A 有一轮已完成但尚未被监听器读取，B 有一轮尚在生成。停止成功后，A 的这一轮可回读；B 随后完成回答，重启后仍跳过这一轮。
3. 在空目录查状态，检查未创建项目文件。另在主动停止的项目查状态，从返回的链接打开白板、核对原文轮数和整理进度，再继续对话。再次查状态确认轮数未增加、会话仍处于停采状态。
4. 在未配置模型且没有图形桌面的终端调用技能，确认绑定生效、后续原文可回读，回执给出专题链接和模型状态。要求“打开白板”时仍只打印链接。
5. 停止时让会话 A 的原文暂时不可读。核对所有会话均已停采、回执点名 A；恢复可读后，停止期间的问答始终留在专题之外。
6. 保存三轮问答并修订第二轮。状态仍显示三轮，第二轮的两个版本均可回读。
7. 项目 A 正在采集时更新源码并重跑安装，确认 A 继续记录。此后新启动的项目 B 使用新版。另验证安装失败时原入口仍可用。
8. 项目内准备三个专题，从未绑定的会话调用 `$bang status`。逐行核对三个链接打开各自的专题、各专题的采集会话和整理进度正确，查询前后的绑定一致。
9. 分别从已绑定且监听生效的 Codex 和依赖逐轮投递的宿主调用技能。核对启动回执，并在白板来源中回读 Codex 自动采集的一轮和另一宿主实际提交的一轮。
