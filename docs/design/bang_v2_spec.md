# Bang v2 单人认知路标白板规格

## Problem Statement

一个人围绕同一专题在多个会话里学习、做实验或讨论设计。两周后再打开白板，他需要找到当前结论、成立条件、仍有分歧的问题，以及促成修正的那轮原文。现有运行时分散，普通画布缺少稳定的语义和来源锚点。逐轮堆卡又会淹没真正值得回看的转折。用户还需要控制哪些对话进入专题，并相信自己的文字、连线和布局在后台同步或换机器后仍能找回。

## Solution

交付附着于原生对话工具的单人认知路标白板。用户选定专题并绑定会话，继续正常讨论。Bang 在本地保存采集范围内的原始轮次记录（Episode），从中提炼少量路标，随新证据更新专题。用户可以从结论追到原文、修正白板、在另一台自己的设备恢复专题。

## User Stories

1. 作为专题作者，我希望创建、切换和归档专题，以便把不同议题分开。
2. 作为 Codex 用户，我希望从发起绑定的当轮开始记录，以便自行决定专题的起点。
3. 作为用户，我希望绑定指令、操作回执和 Bang 后台会话自动排除，以便原文只包含专题讨论。
4. 作为用户，我希望一句明确的白板改写要求能保存为人工编辑，以便操作和讨论难以分离时仍能修正结论。
5. 作为用户，我希望解绑期间的内容留在专题之外，以便重新绑定后只采集新的讨论。
6. 作为用户，我希望关闭浏览器后继续整理，意外退出后补齐有效绑定期间的对话，主动停止后跳过停采期间的对话，以便无需一直开着白板。
7. 作为用户，我希望两次真实发生的相同问答各自可查，也希望同一版的重复投递只计一次，以便保留准确的讨论顺序。
8. 作为用户，我希望修订来源后仍能回看旧版，以便知道原结论为何失效。
9. 作为多工具用户，我希望 Codex、Antigravity、Cursor CLI 和兼容 MCP 的工具延续同一专题，以便切换会话工具时仍能查询已有依据。
10. 作为用户，我希望无新理解的轮次可以只保存原文，以便重复确认不会增加卡片。
11. 作为学习者，我希望单独记录掌握度、立场和误解纠偏史，以便个人认知的变化能与知识正文分别查看。
12. 作为研究者，我希望看到成立条件、争议双方、未决问题和被替代的旧判断，以便判断一条结论何时仍可使用。
13. 作为读者，我希望从结论打开原文抽屉，并区分对话明示与模型归纳的关系，以便核对证据。
14. 作为白板作者，我希望编辑节点正文、条件、边端点和谓词，以便保留自己认可的准确表达。
15. 作为白板作者，我希望只在出现直接相关的新依据时再看到已忽略的修改建议，以便反复同步时专注于真正的变化。
16. 作为读者，我希望固定、拖动或折叠路标，并按学习、决策或演进查看专题，以便在熟悉的位置继续阅读。
17. 作为读者，我希望回放结论演化时跳过纯坐标修改，以便识别真正的语义变化。
18. 作为用户，我希望查看队列状态、立即同步并重试失败会话，以便其他会话能继续工作。
19. 作为多设备用户，我希望导入快照时沿用可确认的较新状态，以便旧快照不会回滚手改。
20. 作为多设备用户，我希望双方分叉或关系不明时留存两份完整内容，以便自己决定取舍。
21. 作为本地用户，我希望原始对话和凭据留在本机，能选择兼容 API、Codex CLI 或本地模型，以便控制整理方式和可提交到 Git 的内容。

## Implementation Decisions

- TypeScript 工作区分核心引擎、适配器和 Web 客户端。Node ≥22.13 的原生 SQLite 使用 WAL，作为唯一写入权威。保存专题、Episode、游标、会话子图、作业、语义版本和布局。提交后确定性导出知识、个人认知和布局三份快照；原文库、进程凭据与模型密钥留在本地。
- 默认显式绑定。绑定当轮取其可独立辨认的专题问答，轮间绑定从下一轮开始。纯操作轮只推进游标；操作与专题内容无法分离时跳过整轮原文，明确的人工修改照常保存并锁定。排除内部整理器及设计中指定的子代理、分支会话。解绑结束采集区间；重新绑定开启新区间；同一专题可同时绑定多个会话。主动停止项目结束其全部采集区间，保存收到停止请求时已经完成且符合采集规则的轮次，跳过当时仍在生成的回答；意外退出保留绑定、游标和半行缓冲。
- Episode 是一次真实轮次的一版原文。按专题、来源工具、会话、稳定来源轮次标识及修订关系识别投递。同版重投返回已有记录，只增加一次防抖计数；修订追加并链接前版。已绑定的 Codex 会话中，MCP 缺少 watcher 共用的原生轮次标识时返回 `watcher_managed`，调用方仍可查询和同步。多专题路由不明确时要求选择专题。聊天中调用 `$bang` 时，新目录用目录名创建专题；已有绑定优先，无绑定则沿用唯一活跃专题，多个候选时由用户选择。
- 约 4–6 轮、静默 90 秒或手动同步触发整理。Pass 1 维护会话内增量，软预算每会话 3–7 个路标，可无变动。Pass 2 用全局轻量索引和局部详稿跨会话归并，保留争议及近期被替代节点。支持补充依据、限定、反驳、替代、闭合问题、个人认知更新和按需聚类。作业按会话隔离，失败退避后可显式重试。
- 区分原文、客观知识、个人认知。知识图采用四类节点、九类结构边与自然语言谓词。保留讨论时间、领域事件时间和记录时间。自述理解只记为自报；后续推导、实验等依据或人工确认可支持验证。语义和认知变更递增语义版本；纯布局变更独立保存。
- 人工编辑携带基础版本，互不相交的更新可合并。对锁定字段或锁定边的冲突形成待审阅建议。忽略记录随专题保存；按目标、字段、改法和依据辨认重复建议，改写理由或引用换序均不再提醒。新依据触发重提时展示新增依据。
- React Flow 白板以安静的自然视图起步，空专题只有轻量状态。按局部关系选择依赖、流程、对比或发散布局。增量更新保护固定节点和无关簇的位置。提供详情、条件、来源、纠偏和建议抽屉，以及局部动效和减少动态效果支持。
- 提供 CLI、五个 MCP 工具、本地 HTTP 和 SSE。单项目守护进程按需启动并发现端口，校验回环地址、Host、Origin 和凭据。终端技能输出专题的一次性链接，由用户自行打开。`$bang status` 可按需启动已有专题的白板服务并逐项列出所有专题的名称、链接、采集会话和进度，无需先选择专题。技能回执说明当前会话采用自动监听还是宿主逐轮投递。浏览器使用一次性交换建立会话。模型提供方经统一结构化输出接口接入；Codex 整理子进程使用独立临时目录、只读沙箱及内部会话标记。
- 显式导入时联合比较语义、认知和布局。新专题建立基线，内容相同跳过。可核实祖先关系时沿用较新端；仅布局变化只写布局。分叉或关系不明时停止导入并保护两份内容，包括防止后续自动导出覆盖待选快照。文件时间或较大的语义版本号不足以判定先后。导入设备缺少原文时明确提示。

## Testing Decisions

- 未配置整理模型时照常绑定和保存原文，并提示配置状态。已保存原文轮数按实际对话轮次统计，同轮修订保留各版且只计一轮。
- 主动停止时若来源暂时不可读，仍结束全部绑定，回执列出无法核实尾部的会话。恢复时仅补入能确认在停止前完成的有效轮次。
- 在空目录查询状态时不创建项目。主动停止后调用 `$bang status`，可通过返回的链接回看专题，并查看已保存原文轮数和最近成功整理进度。服务恢复后各会话仍处于停采状态。
- 使用已确认的两个用户入口。核心采集、队列、归并与恢复通过临时项目中的 CLI/MCP 驱动，通过 inspect、状态、原文和导出结果断言；白板通过浏览器执行真实编辑、拖拽、建议审阅与抽屉操作。验收以可观察结果为准。
- 从第 12 轮绑定，验证前 11 轮排除；覆盖纯指令、可分离和不可分离的混合轮。分别模拟解绑重绑、项目主动停止后重绑跳过间隔、意外退出续传、半行输入及服务强杀。让 MCP 在 watcher 读取前后投递，验证一次入库、一次计数、两个同文真实轮次分别可追溯。
- 运行冻结 Q01–Q20，每案三轮保留全部输出与错误，执行真实的人工编辑前置步骤。使用原 0/1/2 评分规则，各适用维度无 0 分、均值至少 1.8。任一轮丢失手改、编造来源或继续使用已撤回前提即失败；缺跑不能判通过。追加 GDN/Delta Rule 学习和架构讨论的真实多会话案例，用 inspect 核对问题、纠偏来源和当前条件。
- 用包含三个会话的专题从结论打开完整条件和对应 Episode；同步后复查手改正文和边端点；忽略建议后分别用同一依据和直接相关的新依据重试。向一个簇新增节点，核对另一簇坐标；拖拽后核对语义回放版本数。
- 验证并发采集与人工操作、单会话失败隔离、多项目端口发现，以及本人跨设备恢复。导入覆盖空库、重复导入、单边更新的两个方向、纯布局更新、双方分叉、不可证明先后，以及冲突后的再次自动导出。

## Out of Scope

多人协作与多人认知状态、Claude 生态接入、绑定前历史回填、按轮强制建卡、要求用户限时复述思考脉络，均不属于 v2。Git 快照恢复不包含原采集设备的完整对话库。

## Further Notes

按五个阶段交付：存储与本地服务、语义引擎与评测、可编辑白板、视角与回放、多工具接入及完整恢复。迁移时保留冻结用例、评分基线和原始产品需求，逐步替换旧运行时、签验和画布原型。以上验收是交付条件，尚未作为 v2 实现运行。
