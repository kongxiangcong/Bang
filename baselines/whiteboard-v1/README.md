# Ticket 01 baseline and evidence

This is a synthetic, source-controlled baseline, frozen before new whiteboard implementation and model evaluation. Source: c3993b760a9f03553694ca32e52281a9087a5ac8. `manifest.json` fixes the actual dependency lock hash, installed direct versions, reference machine and fixture SHA-256 values. Existing shared node_modules was reused through a worktree-local junction; npm ls reported extraneous packages. No clean-install or packaged-install claim is made.

## Public boundaries

`runCompanion(argv, options)` runs the existing companion commands. Default CLI arguments, source reading, model process arguments and writes are retained. Options inject project root, model process launcher and command output only. The existing `--transcript` remains the host-source boundary. Import no longer executes a CLI command. Errors still log and CLI failures still exit nonzero.

`createBangMiddleware({projectRoot,beforeReplace})` keeps the existing browser HTTP interface. The optional no-op fault hook fires between writing the candidate session and replacing it. It does not replace filesystem IO or the save path. It is a test seam, not a crash-consistent transaction or security feature.

## Frozen materials and future measurement

- `legacy-session.json`: synthetic old schema with manual text, deleted object and manually routed arrow; demonstrates legacy fields without copying private data. Companion-format old data is generated by the synthetic public-command test. Full migration coverage is ticket 37.
- `quality-cases.json` + `scoring.md`: 20 fixed cases, five each in learning, meetings, comparison and research, three runs each; blocking failures and anchored scoring predeclared. No model quality scores have been obtained.
- `performance-dataset.mjs`: deterministic generator for 1,000 nodes, 3,000 distinct directed edges, 10,000 revision edits, no attachments. `performance.json` fixes warmups, sample count, nearest-rank p95, idle/model-busy conditions and timing endpoints. Use the manifest machine as the Windows reference; document power mode, background load and browser version for each run. Do not compare cross-machine results as improvements.
- Save/refresh/history target latency, compilation duration, peak RSS and 10,000-round file-growth stress are NOT measured. The legacy prototype has no shared revision/history contract, so reporting those targets as passing would be misleading. These are frozen future measurements, not invented performance numbers. The revision workload and round-count workload are distinct.

## Known unchanged limitations

The browser autosaves scenes; these are not common semantic commits. Companion state/board/source files are separate writes with no prepared/recovery protocol. PID-file locking is not OS ownership; view saves have no revision conflict control. pause and stop are equivalent in this legacy runtime. Browser rendering supplies layout; no independent headless compiler exists. The old scripts that depend on personal PIM replay files and scripted interception were not executed here; their existence is not acceptance evidence.

## Real-host and platform gaps

No Codex or DSH model was invoked. Authentication, automatic completed-turn acquisition, next-turn context delivery, process-tree cancellation and full host loop remain unverified. Only this native Windows 11 machine was exercised. Windows 10 and Ubuntu, packaged install, read-only installation, external editor interoperability, IME/accessibility, power loss and disk corruption remain unrun. A real browser test is not real-host evidence.

Ticket 01 acceptance is limited to isolating the old public entry, preserving tested old save/reopen behavior and freezing baseline inputs and conditions. It does not pass T32 performance or quality targets, nor any future ticket's behavior.
