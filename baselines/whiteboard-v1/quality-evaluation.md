# 第 43 张票的冻结质量验收

[冻结样例](quality-cases.json)包含学习、会议、比较和科研各 5 例，每例安排 3 次独立运行。[评分表](scoring.md)规定逐维度和阻断错误。验收程序对照 [manifest](manifest.json) 核验样例与评分表的 SHA-256，逐例保留结果、失败和空结果。每次运行创建独立的临时项目和签名来源，运行后从公共接口重开读回，再停止进程并清理临时项目。证据目录必须是新目录，中断后保留现有目录和已计划但未完成的槽位。

## 生成预案与受控证据

在仓库根目录运行。命令使用仓库提供的对应平台原生辅助程序，Windows 验证需要允许本机子进程和回环通信。

```powershell
node tests/whiteboard-quality.mjs plan .scratch/q43-plan
node tests/whiteboard-quality.mjs controlled .scratch/q43-controlled
node tests/whiteboard-quality.mjs controlled-failure .scratch/q43-invalid-source Q10
```

`controlled` 可追加受控冒烟所需样例编号。默认执行全部 60 个槽位。`controlled-failure` 使用故意错误的来源 ID，预期保留三次拒绝和候选原文并返回非零退出码。两者都由原生 Runtime 执行正式 Codex 整理器适配器、结果校验、确定性编译、保存和重开。外部 CLI 与聊天来源为受控替身。回送使用独立签名的 ContextBridge，带受控宿主回执。受控结果只能说明这些路径执行及其确定性约束，质量表保持空白。

- Q09 先用两次实际保存可见地把周五改为下周二。受控候选补充测试项，保存的人工正文应保持。
- Q14 先保存证据指向 A，再用实际保存把端点改为 C。受控候选触发整理，人工改接应保持。冻结讨论未给出 B 说明的新正文，后续由评审依冻结要求判定，预案不补造事实。
- Q15 实际保存两个互不相干的区域，证据记录两区完整坐标及层叠顺序。受控候选只向存储区域增加关系，网络区域应保持。受控证据文字仅用于检验隔离。
- Q05、Q17、Q20 先接收并整理一版来源，暂停整理后以相同 turn ID 接收冻结的更新版本，保存版本切换快照再继续整理。旧来源通过公开版本历史保留，受控候选验证待复核对象以及后续回送的有效知识排除旧依据。早期版本是评分表要求的准备数据。
- 其他样例的受控输出用于检查相同路径是否可重复执行。源文本、所需条件、关系和结构的语义评分保留给独立评审。

## 独立评审与真实模型运行

先运行 `plan`，让评审者仅根据冻结输入填写 `applicability.json`，逐例逐维标注是否适用并说明不适用理由。真实模式只接收完整的预登记文件，固定执行 60 个槽位，保留该文件及哈希。真实服务运行需要获准的 Codex 可执行文件、认证目录和请求预算。将可执行文件与认证目录的绝对路径分别通过 `BANG_QUALITY_REAL_BINARY` 和 `BANG_QUALITY_AUTH_HOME` 传入。启动器使用生产适配器固定的版本和模型 `codex-cli 0.169.0-alpha.11.1` / `gpt-6.1-sol`，保留生产沙箱和禁用工具参数。需要已有代理时，显式设置 `BANG_QUALITY_INHERIT_PROXY=1`。这些值仅用于当前执行进程。

真实证据采集器只转发生产适配器的版本、登录状态、内置模型目录和受限整理命令。认证目录通过本机 `CODEX_HOME` 环境交给已获准的 Codex 可执行文件。整理输入由冻结合成来源和独立临时白板组成。

```powershell
node tests/whiteboard-quality.mjs real .scratch/q43-real .scratch/q43-plan/applicability.json
```

每个槽位最多消耗一次整理请求预算，Q05/Q17/Q20 各增加一次用于早期版本，共计最多 69 次预算内尝试。单次整理尝试的超时为 90 秒，实际费用和服务端重试以提供方口径为准。真实模式使用真实 Codex 整理器推理和同一套合成已完成轮。实际 Codex 聊天 Hook 信任、自动接收和真实下一轮使用知识需另有宿主证据。固定版执行器没有已验证的服务端种子设置，真实预案显式记录 seed 为 null，在确认能够满足冻结种子条件前仍不能据此判定完整门槛通过。

每个槽位的 `candidate-*.jsonl` 保存送入限定适配器的准确合成 prompt、schema/catalog 哈希、候选原文、使用量和终态。错误另外保留 Runtime 的错误码、阶段、原因、任务回执及无提交的结果。原始工具内容、推理、provider stderr 与潜在敏感的非 JSON 输出不进入证据。逐次证据包含人工保存操作、来源 ID 和历史、整理前后白板、依据和结构、受控回送及重开结果。`index.json` 汇总采集状态。`captured` 标记运行和取证完成。

评审者对照冻结样例与评分表填写 `scoring-form.json`，记录评审人、修订、原始来源 ID、各维度分数及理由，并标注阻断错误。汇总时，每个适用维度须无 0 分且均值至少 1.8。任何人工修改丢失、伪造依据、继续使用撤回前提，以及运行缺失或失败，均阻止通过。运行程序保留评审表，不推断语义分数或评判模型质量。
