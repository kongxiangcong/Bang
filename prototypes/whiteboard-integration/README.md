# Bang

对话中的模型负责理解目标、关系和推导，Bang 将语义增量显示在同一张可编辑白板上。输入不预选模板；分类、发散、独立疑问、执行或证据顺序可采用不同表达，并随讨论改变。图中文字、解释与原文来源一起保存和撤销。

## 启动

```powershell
cd prototypes/whiteboard-integration
npm ci --registry=https://registry.npmjs.org
npm run dev
```

从仓库根目录执行以上命令，打开 http://127.0.0.1:5180/ 。本次已在 Node 25.8.1、Chrome 上运行。`predev` 会准备本地字体与 ELK Worker。新克隆没有个人 PIM 原文时，根页面创建空白讨论；PIM 回放需要另行提供原文与已整理的本地增量。

后台专题使用 `http://127.0.0.1:5180/?topic=<已初始化的专题>`。该页面自动接收后台新 revision，独立保存到 `.bang/topics/<专题>/view.json`；根地址保留手动整理或 PIM 回放。后台接收每轮对话、独立模型整理与文档落盘均不依赖网页打开。初始化及运行步骤见 [后台运行说明](../../runtime/companion/README.md)。当前服务默认读取 Bang 仓库；外部工作区需要在 `vite.config.ts` 给 `createBangMiddleware` 显式配置 `projectRoot` 并重启。

## 在对话框使用

引用项目内 [Bang 技能](../../skills/bang/SKILL.md)，例如：

> 使用 `D:\dsh-proj\Bang\skills\bang\SKILL.md`，把当前讨论整理到 Bang，并继续更新这张白板。

技能随项目交付，尚未全局安装，不能假定宿主已经识别 `$bang`。这个技能仍是手动整理入口，不会自动初始化后台陪伴。当前对话模型读取实际白板上下文，判断讨论目标和内容关系，写出带推导与来源的增量，通过本地 CLI 提交；没有另开付费模型 API，也没有用关键词规则冒充语义理解。

CLI 与服务默认连接 5180，使用：

```powershell
node bang.mjs context
node bang.mjs submit ../../.bang/submissions/my-update.json
```

增量格式见技能的 [协议](../../skills/bang/references/protocol.md)。原文和增量一起提交后，打开的白板接收更新。后续调用沿用会话和对象 id，用户改写与新判断冲突时保留当前文字，展示可采用的更新建议。

## PIM 回放

原始输入是项目根目录 `PIM架构探索讨论.md`。本次 agent 按原文前缀顺序阅读后，将语义增量记录到本地 `.bang/fixtures/pim-plans.json`；这是可重放的语义结果，不是运行时自动调用模型。

- “下一条”显示一条用户或模型原文，“播放”按顺序播放，“暂停”停住，“重播”清空当前活动会话并从原文开始。
- 默认每两轮完整问答更新一次：第 2、4、6、8、10、12、14、16、17 轮，共 34 条消息、9 批。第 17 轮单独收尾。
- 逐步形成 5 个内容区域、30 个节点、28 条关系。后期证据使独立事项改为时序链；旧预测为何失效保留在解释中。
- 自动更新保持当前视角；“全景”和区域标题可主动聚焦。完整回放后，可用同一技能提交后续讨论。
- 回放实例中“1161 CK”仍是有前提的预测；四组映射触发 256、误差零是用户报告，没有补造端到端加速结论。

通用新讨论可显式运行 `node bang.mjs reset --empty --id <topic>`。它替换当前活动会话；当前版本是单用户、单活动会话，没有多专题管理。

## 已验证

`npm run build` 通过 TypeScript 与生产构建（仍有包体较大的构建提示）。在服务运行时执行：

```powershell
$env:BANG_URL='http://127.0.0.1:5180'
npm run validate
```

脚本会重播当前测试会话，然后模拟两次后续讨论。2026-11-15 实测通过三条完整流程：

1. 34 条消息逐条进入，9 个正确批次更新；每批节点来源只引用已出现消息，最终 5 区/30 节点。
2. 实际执行 `bang.mjs context/submit` 追加第 18 轮，浏览器同一白板收到增量；无关对象不变，重试同事件不重复，撤销/重做同步恢复文字和依据。
3. 用户手改后再次从 CLI 续接讨论，生成建议而不覆盖；采用建议后保存并真实刷新，文字、来源、节点位置、事件游标恢复。编辑器会对箭头端点做约 0.5px 的恢复规范化。

运行时异常 0，测试中的外部网络请求 0。结果：`evidence/replay/results.json`；截图：`first-batch.png`、`full-replay.png`、`continuation.png`。测试会话包含两次模拟后续输入；点击“重播”可回到原始 PIM。

实际修复：HTTP 分块读取按 Buffer 拼接后统一 UTF-8 解码，避免中文跨块损坏；表达变化仅重排相关区域的自动位置，手摆位置保留；更新关系时同步绑定端点与反向引用；新增内容与冲突建议使用同一编辑器历史。

## 实现边界

连线修复（2026-11-15）：生成器改为沿卡片法向出入的正交折线，自动绕开中间卡片；节点拖动结束后重算自动连线。旧场景载入时修复自动连线，保留卡片位置、文字与依据。Windows 上 Ctrl+双击连线可进入端点/折点编辑；普通双击编辑线上的文字。人工调整的连线会保留，后续同端点关系更新不覆盖；技能提交新的关系端点时按新关系重新连接。原生手调只保护走线与端点落点；直接拖到另一张卡片不会自动修改 Bang 的语义 from/to，关系改接仍应通过技能提交。

`node validate-connectors.mjs` 使用当前场景副本并在浏览器拦截全部会话 API，不重播、不写回用户会话。已验证 28 条线无端点偏离或穿过无关卡片、原生节点拖动、Ctrl+双击后拖端点、后续更新保留手调，以及保存刷新恢复。结果在 `evidence/connectors/results.json`，截图在 `repaired-overview.png`。

- React/TypeScript/Vite + Excalidraw 0.18.1；d3-hierarchy 处理分类/发散，ELK Worker 处理顺序；Zustand 只管详情焦点，Radix 提供详情标签页。
- Vite 本地中间件保存 `.bang/sessions/pim.json`，包含原文、语义事件、实际场景与应用游标。浏览器是场景编辑者，技能通过 submit 提交语义。当前需要本地开发服务；不能把静态 dist 单独部署后声称后端仍可用。
- 本地技能桥接已跑通，尚未制作宿主插件安装包或自动全局注册。宿主实际读取技能后的开放式语义质量没有做独立模型评测，本次验证的是当前 agent 整理结果和实际传输/编辑流程。
- 不含多用户并发、跨设备同步、长期版本浏览；撤销栈不跨刷新保存。中文真实 IME composition、触摸、大型图与复杂富文本尚未测。
- PIM 原文、回放语义数据、会话、提交数据与截图保持 Git 忽略。clone 后要准备自己的原文和语义数据，或先用 `reset --empty` 开始通用讨论。代码中没有固定 PIM 分类器。

许可证以安装包为准：主要前端依赖为 MIT，d3-hierarchy 为 ISC，TypeScript 为 Apache-2.0，ELK 按 EPL-2.0 使用；字体保留各自通知。无需商业白板 SDK key。
